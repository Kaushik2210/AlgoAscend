# Platform research

| Platform | Observed learning pattern | AlgoAscend design decision |
| --- | --- | --- |
| [LeetCode 75](https://leetcode.com/studyplan/leetcode-75/) | Curated interview practice | Connect each lesson to a specific transfer problem. |
| [Codeforces EDU](https://codeforces.com/edu/courses/?locale=en) | Topic-based competitive programming lessons | Introduce contest constraints after the learner understands the core idea. |
| [CodeChef](https://www.codechef.com/faq/) | Language roadmaps and gradual contest difficulty | Let students choose a language before entering the practice path. |
| [HackerRank](https://help.hackerrank.com/articles/1723224478-introduction-to-prep-kits) | Structured preparation and tutor-supported challenges | Keep hints close to the task and expose one at a time. |
| [AtCoder Practice](https://atcoder.jp/contests/practice) | A practice contest teaches the submission workflow | Give beginners an explicit path from the first example to their first submission. |
| [VisuAlgo](https://visualgo.net/en) | Algorithm visualization with lectures and quizzes | Make stepping backward and changing inputs part of the experiment. |
| [Python Tutor](https://pythontutor.com/) | Stepwise program execution across languages | Show the values and pseudocode associated with each decision. |
| [USACO Guide](https://usaco.guide/) | Divisional learning paths with modules and problems | Show the entire route and identify which stages have published lessons. |
| [Brilliant](https://brilliant.org/about/) | Interactive, adaptive problem-solving | Ask learners to commit to a prediction before seeing the explanation. |

AlgoAscend combines these ideas in one loop: predict a decision, replay the state change, explain what made it valid, then implement and test. The visual language is an original technical field guide built around the learner’s actual inputs. The first lesson tests whether the loop makes it easier to explain why discarding half of a sorted array is safe.
